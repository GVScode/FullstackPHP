Manual de Boas Práticas de Desenvolvimento

Versão 1.0 — Agosto de 2026

1. Introdução

Este manual reúne as diretrizes adotadas pela equipe para garantir qualidade, consistência e produtividade no desenvolvimento de software.

1.1 Objetivo

Estabelecer padrões claros para que todos os membros do time produzam código legível, testável e sustentável.

1.2 Público-alvo

Desenvolvedores, analistas, QA e qualquer pessoa envolvida no ciclo de vida do software.

2. Organização do Projeto

Uma boa organização facilita a manutenção e a entrada de novos membros no projeto.

2.1 Estrutura de pastas

  • src/ — código-fonte principal
  • tests/ — testes automatizados
  • docs/ — documentação
  • scripts/ — utilitários e automações

2.2 Nomenclatura

Utilize nomes descritivos em inglês, seguindo o padrão camelCase para variáveis e funções, e PascalCase para classes.

3. Estilo de Código

Manter um estilo consistente reduz o ruído cognitivo durante revisões.

3.1 Indentação

Use 2 espaços por nível de indentação. Configure seu editor para aplicar essa regra automaticamente.

3.2 Comentários

Comente o porquê, não o o quê. O código deve ser autoexplicativo; comentários servem para explicar decisões não óbvias.

4. Controle de Versão (Git)

O Git é a ferramenta oficial de versionamento. Siga as convenções abaixo.

4.1 Mensagens de commit

Use o padrão Conventional Commits: tipo(escopo): descrição. Exemplos: feat(auth): adiciona login com 2FA, fix(api): corrige timeout.

4.2 Branches

  • main — produção
  • develop — integração
  • feature/*, fix/*, hotfix/* — branches temporárias

5. Revisão de Código

Toda alteração deve passar por pelo menos uma revisão antes de ser integrada.

5.1 Checklist

  • Código segue o estilo definido
  • Testes foram adicionados/atualizados
  • Documentação relevante atualizada
  • Sem credenciais ou dados sensíveis
