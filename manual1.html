1. INTRODUÇÃO

Este Manual destina-se a orientar o programador/analista de sistemas que irá utilizar o OPUScase para a geração de rotinas.

1.1 Introdução ao OPUScase

O OPUScase é um produto do tipo I-CASE (Integrated Computer Aided Engeneering). Permite aos profissionais de informática desenhar e gerar aplicações de forma rápida, fácil, segura, livre de erros de sintaxe e auto-documentada, possibilitando desta maneira uma maior produtividade no desenvolvimento de sistemas computorizados.

O OPUScase é composto de:

  • Dicionário de Dados
  • Editor de Telas de Entrada/Saída
  • Linguagem 4GL em português
  • Gerador de Rotinas em linguagem C
  • Gerenciador de Banco de Dados
  • Documentador de Manuais

1.2 Quem deve usar este manual

Este manual deve ser utilizado pelo pessoal técnico que irá desenvolver rotinas através do OPUScase, servindo como fonte de consulta para dirimir eventuais dúvidas que venham surgir na utilização do sistema.

1.3 Pré-Requisitos

Para desenvolver rotinas em OPUScase, apesar de ser fácil e simples, é recomendável que você tenha o conhecimento dos seguintes assuntos:

  • Conhecimento de Análise Orientada por Objetos.
  • Funções Básicas de Unix.
  • Programação em linguagem "C".

1.4 Como Interpretar a tela de uma rotina

As rotinas geradas pelo OPUScase seguem a padronização SAA-CUA (System Architecture Application - Common Users Access). Exemplo de layout:

+---------------------------------------------------------------+
| 1 ---> OPÇÃO  AJUDA                                           |
| 2 ...> MENU   IDENTIFICA                                      |
|    PRGID      NOME DA APLICAÇÃO             TTY               |
| 4 .>                                                          |
| 5 ...>                                                        |
| 6 ..-> Mensagem:                                              |
|    F01=HELP  F03=SAIDA                                        |
+---------------------------------------------------------------+
  • Barra de Ação: Acionada pela tecla F10. Elementos: OPÇÕES, MENU, IDENTIFICA e AJUDA.
  • PRGID: Exibe o Código da rotina em execução.
  • TTY-DD: Exibe o número do terminal AIX (tty) e OPUScase.
  • Área de Trabalho: Onde se visualiza o lay-out da rotina.
  • Área de Mensagem: Disponível para mensagens do Sistema ao usuário.
  • Teclas de Ação: F01 (HELP), F03 (SAÍDA), F10 (AÇÃO), F12 (ELIMINA).

1.5 COMO FUNCIONA O TECLADO

A execução de uma rotina implica na digitação de informações nos campos solicitados. O sistema permite:

  • Movimentação: Ctrl K/↑ (anterior), Ctrl J/↓ (próximo/enter), Ctrl H/← (esquerda), Ctrl L/→ (direita).
  • Deleção: Ctrl T (apaga resto), Ctrl G/Delete (apaga caractere), Ctrl D (limpa campo).
  • Inserção: Ctrl I ou Insert (muda modo Inserção/Substituição).

1.6 COMO FUNCIONAM AS ROTINAS

A execução obedece aos seguintes critérios: da esquerda para direita e de cima para baixo. O campo é classificado em: Obrigatório, Não Obrigatório ou Faixa.

As rotinas são classificadas em: Data-entry, Impresso, Opções, Relatórios, Sub-rotinas e Tabelas.

1.7 Como ler os diagramas de Sintaxe

  • Ler o diagrama da sintaxe da esquerda para a direita e do topo para baixo.
  • O símbolo ► indica o começo do comando.
  • Palavras-chave aparecem em letras maiúsculas e devem ser especificadas exatamente como mostradas.
  • Variáveis aparecem em letras itálicas e representam valores fornecidos pelo usuário.

1.8 ACESSANDO O OPUScase

Através da execução da Rotina OPUS o usuário acessa a tela de identificação. Após informar Empresa, Filial e Almoxarifado, o sistema exibe os sistemas habilitados. Informando "YLA" no campo SMR, acessa-se a tela principal com a Barra de Ação: ATRIBUTOS, ENTIDADES, ROTINAS, DESENVOLVE, DOCUMENTAÇÃO.

2. DICIONÁRIO DE DADOS

Dicionário de Dados é o conjunto das definições e especificações dos atributos e entidades, únicos no sistema. Contém as informações necessárias para a consistência dos atributos utilizados e as diretivas para a atualização e recuperação da informação na base de dados.

2.1 ATRIBUTO

Atributo é a designação dada a uma informação determinando o formato e suas consistências. É único no sistema.

Elementos da especificação de um atributo:

  • Banco: Caractere alfabético identificador do projeto.
  • Atributo: Forma reduzida da identificação (até 7 caracteres alfanuméricos).
  • Denominação: Nome do atributo (até 30 caracteres).
  • Tamanho: Quantidade de caracteres.
  • Fixo/Variável: (F) preenchimento completo ou (V) até o limite.
  • Formato: A (Alfabético), D (Data), E (Qualquer), H (Hora), M (Alfanumérico), N (Numérico), V (Monetário).

2.2 ENTIDADE

É a designação dada a um conjunto de definições de um determinado objeto, agrupadas em: Cabeçalho, Registro e Visões.

  • Cabeçalho: Tipo de arquivo, chave principal e diretório.
  • Registro: Todos os campos que compõe o arquivo.
  • Visões: Chaves secundárias de acesso ao registro (até 10 visões, de 0 a 9).

3. COMANDOS

A linguagem OPUScase contém inúmeros comandos que podem ser usados pelo programador na criação de rotinas. Cada comando realiza ações definidas pelos argumentos e operadores associados.

3.2.1 Comando APAGA

Propósito: Eliminar todas as informações de uma entidade que estejam vinculadas ao nível informado.

------ APAGA ----- entidade ----- , ----- nível --------

Exemplo: APAGA EPRODU,2

3.2.2 Comando ASCII

Propósito: Converte um caractere ASCII para seu valor decimal, armazenando-o na variável ASCII.

--------- ASCII ----- literal ------ , ----- posição do atributo -------

3.2.3 Comando CHAIN

Propósito: Verifica a existência de um registro em disco através de um acesso direto ao registro.

----------- CHAIN ------ entidade ---------

3.2.12 Comando FACA

Propósito: Atribuir valores a uma variável.

------------- FACA --------- variável-destino ---------- --------- expressão string --------

Exemplo: FACA A="128" ou FACA A=B_"128"

3.2.28 Comando SE

Propósito: Condicionar todos os comandos ou colunas dentro de um bloco ao resultado afirmativo de seu argumento.

------------- SE ------- expressão relacional ---------------

Operadores relacionais: > (maior), < (menor), = (igual), ~ (não).

3.2.X Demais Comandos (Resumo da Referência)

O manual completo abrange os seguintes comandos adicionais: CHAR, COMENT, COMPUTE, DECLARA, ENTIDADE, EXIBE, EXTRAIR, FIM, GOTO, HABILITA, JANELA, LIMPA, LINHA, MATA, MATATUDO, MENSAGEM, MOSTRA, PARA, PROCURAR, PULAFOL, PULALINHA, RESTO, SELDISP, SELECIONAR, SUBROT, TAMANHO, TECLADO, VARIAR, VERNOS e VERPRO. Consulte a documentação física para a sintaxe detalhada de cada um.

4. BIBLIOTECA DE FUNÇÕES

O OPUScase dispõe de uma biblioteca própria de funções (libadis.a) que podem ser utilizadas em uma rotina.

4.1.1 UDEI / 4.1.2 UDIE (Datas)

  • UDEI: Converte data externa (DD/MM/AA) em data interna (dias decorridos desde 01/01/1900).
  • UDIE: Converte data interna em data externa.

4.1.6 WCAB

Propósito: Executa a operação de impressão do cabeçalho durante a emissão de um relatório. Faz uso das variáveis ZXLP, ZXTP, ZXPG, ZXCL, ZNC e WPROMPT.

5. GERADOR DE ROTINAS

O gerador de rotinas é usado para criar, editar, montar/compilar, documentar e testar rotinas. É constituído de fases sequenciais.

5.1 Acessando o Desenvolvedor de Rotinas

Enderece o cursor, através da Barra de Ação, no campo DESENVOLVE e pressione ENTER.

5.2 Manutenção do Cadastro de Rotinas

Etapa necessária para criar e/ou editar o cadastro. Campos principais: Nome da Rotina, Denominação, Banco, Status (Liberado/Manutenção), Tipo (C, D, I, L, O, R, S, T), Complemento, Formulário, Autor, Box Ocupado, PF Admitidas e Action Bar.

5.3 Desenha Lay-out de Entrada

O OPUScase formata a tela delimitada pelos parâmetros de BOX. Utiliza-se o caractere ] (fecha colchete) para indicar Entrada de Dados (atributos). Teclas de ajuda: Ctrl F (PF's), Ctrl B (Box), Ctrl A (Barra de Ação).

5.4 Lay-out de Saída

Dividido em: Desenha Lay-out (usando o caractere ] para posicionamento) e Agrega Atributos (onde se define Linha, Atributo, Índice, De-Até, Ajuste e Preenchimento).

5.5 Procedimentos Lógicos

Região composta de linhas e colunas (Linha, Rótulo, Comando, Atributo, Entidade, Sub-Rotina, Vai-para, Imprime) onde se programa a lógica da rotina.

Lin  Rotulo  Comando   Atributo      Registro  Sub-rot.  Vai-Para  Imprime
010  INICIO  SELDISP
020  CAB     SUBROT    WCAB                              CAB
030  PESQ    ENTIDADE  TABEST,G                          FIM
040  FIM     FIM

5.6 Gera/Compila

O OPUScase gera um programa fonte na linguagem C e compila gerando um código executável. Caso ocorra erro, deve-se retornar aos Procedimentos Lógicos para correção.

5.7 Executa

Posicione o cursor no campo EXECUTA PROGRAMA e digite ENTER. A rotina é executada pelo OPUScase conforme a sua definição, simulando o ambiente do usuário final.
